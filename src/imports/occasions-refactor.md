Refactor the structure of the Occasions section so that it clearly separates occasion types from actual occasions.

Do not redesign the visual style of the interface. Only adjust the structure and organization of the Occasions area.

The Occasions section should contain two distinct areas:

1. Occasion Types
2. All Occasions


OCCASION TYPES

Occasion Types represent templates or categories that a user can choose when creating a new occasion.

These should function as starting points for creating an occasion.

Remove culturally specific defaults such as Thanksgiving.

Replace the existing categories with the following neutral and flexible occasion types:

Birthday  
Anniversary  
Gathering or Dinner  
Trip or Travel  
Major Milestone  
Breakup or Support  
Illness or Recovery  
Loss or Grief  
Living Will or End-of-Life  
Custom Occasion

Occasion Types should only represent categories for creating occasions. They are not actual events.


ALL OCCASIONS

All Occasions should display the real occasions the user is connected to.

These may include:
- occasions the user created
- occasions another person created that the user is part of
- recurring occasions such as birthdays or anniversaries

Each occasion should appear as a card.

Each card should clearly show:
- the occasion name
- the person or people connected to it
- the date or timeframe
- whether it is recurring or situational

Examples of real occasions:
Sarah's Birthday  
Emma's Surgery  
Grandmother Memorial Anniversary  
Alex and Jordan Anniversary  
Group Trip to Mexico


OCCASION DETAIL PAGE

Occasion detail pages should focus on the life moment itself rather than planning logistics.

Occasion pages may include:
- people connected to the occasion
- key dates
- contextual information
- references to relevant preferences from About Me
- any related plans

Occasion pages should not contain detailed planning tools.

Planning and coordination should live inside Plans.

The purpose of Occasions is to represent meaningful life events and moments connected to people.
